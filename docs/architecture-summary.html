🔧 World & Hooks Design (Cucumber fixture equivalent)
PlaywrightWorld (world.ts)
class PlaywrightWorld extends World { browser: Browser // shared/worker context: BrowserContext // per-scenario page: Page // per-scenario user: any // from user-pool userLockFile: string // released in After limitReached: boolean // quota guard [key]: any // dynamic state }
User Pool (user-pool.ts)
File-lock strategy: fs.openSync(lock, 'wx')
Polls every 250ms · timeout 60 min
Auth state cached: data/auth/<user>.json
Reused via storageState — skips login form

💾 Data Management — 3 Layers
LayerSourcePurpose
L1 data/users.csv Static user pool (email, name, user_id) · parsed by readUsersCsv()
L2 users-config/users.json
gitignored · Docker volume		 Runtime credentials · mounted at container start
L3 data/names.json Cross-scenario state bus: campaign, audience, workflow, existingAudience titles + timestamps
Auth cache: storageState saved to data/auth/<user>.json after first login. Reused until npm run clean.
Unique IDs: Date.now()-process.hrtime.bigint() — collision-free across parallel workers.

⚡ Key Architectural Decisions
DecisionDetail
Cucumber-JS over Playwright Test BDD-first; Gherkin features readable by business stakeholders
No Playwright fixtures Session managed in Given I log in step via user-pool + storageState cache
Shared browser per worker Module-level sharedBrowser; new BrowserContext+Page per scenario → isolation with low overhead
File-lock concurrency fs.openSync('wx') atomic create prevents two workers claiming same user
Limit-reached guard checkLimitReachedPopup() sets limitReached=true; BeforeStep skips remaining steps gracefully
Inline retry loops Login + navigation steps retry 3× with 3s delay — no external retry library
